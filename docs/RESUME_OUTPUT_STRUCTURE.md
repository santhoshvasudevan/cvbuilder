# CVBuilder V2 Resume Output Structure

**Status:** Proposed V2 contract  
**Date:** 2026-09-08

## 1. Purpose

Define the structured content generated by Agent Builder in V2. Initial V2 deliberately limits LLM-generated content to the sections where tailoring quality matters most.

## 2. Structured Output

```text
ResumeDraft

target_title_options[3]
recommended_target_title

professional_summary

experience_sections[3]

key_achievements[]

skills[]
```

Deferred from LLM generation:

- `selected_projects[]`
- `certifications[]`
- `languages[]`

## 3. Target Titles

The LLM proposes exactly three best-matching titles plus one recommended title. The operator may edit them.

## 4. Professional Summary

One tailored summary aligned to the approved APS strategy. It should communicate candidate thesis, relevant seniority, strongest domain/technical positioning, differentiators, and target-role alignment.

## 5. Professional Experience

There are exactly three generated professional-experience content sections, one per active primary `ExperienceSlot`. `ExperienceSlot` is a related, sequenced collection, not fixed database columns; a HARD_INTEGRITY check enforces exactly three `is_primary=True, is_active=True` slots before this stage may run (V2-D024). Which engagements become those three slots is always an explicit operator choice, never automatic (V2-D031).

```text
ExperienceSectionDraft
    experience_slot_id
    bullets[]
```

The renderer resolves static metadata from `ExperienceSlot`:

```text
company_name
role_title
location
start_date
end_date_or_present
```

The LLM generates only `bullets[]`.

Rules:

- bullet count may vary by role relevance;
- most relevant/recent experience may receive more bullets;
- older experience may be compressed;
- avoid repeating the same achievement across sections;
- strong transferable evidence may be used even without literal JD keyword match;
- potential overstatement is a `SOFT_REVIEW_WARNING` — it creates an operator warning, never automatically erases useful content; only `HARD_INTEGRITY` failures (malformed output, dangling references, static-metadata replacement attempts, wrong experience-slot cardinality) block the draft (V2-D026).

## 6. Key Achievements

`key_achievements[]` contains high-value achievements strengthening the role-specific candidate thesis. Avoid duplication with experience bullets.

## 7. Skills

`skills[]` contains selected role-relevant skills. Skills may be grouped, for example, into GenAI/AI, Architecture, Cloud/DevOps, Data, Automotive/Domain, Product/Leadership.

## 8. Deferred Sections

### Selected projects

Deferred but retained as a future extension point.

### Certifications

Not LLM-generated initially; may later be inserted from static content.

### Languages

Not LLM-generated initially; may later be inserted from static content.

## 9. Markdown Rendering Contract

```markdown
# [Recommended Target Title]

## Professional Summary

[Professional Summary]

## Professional Experience

### [STATIC Role Title] — [STATIC Company]
[STATIC Location] | [STATIC Dates]
- [generated bullet]
- [generated bullet]

### [STATIC Role Title] — [STATIC Company]
...

### [STATIC Role Title] — [STATIC Company]
...

## Key Achievements

- [generated achievement]
- [generated achievement]

## Key Skills

[generated/selected skills]
```

Static metadata always overrides accidental model-generated duplicate metadata.

## 10. Human Review

Gate 2 shows structured draft, rendered markdown, static metadata separately, deterministic warnings, recruiter critique, and optional quality score. Deterministic warnings are split into `HARD_INTEGRITY` (blocking) and `SOFT_REVIEW_WARNING` (advisory) classes — see `docs/ARCHITECTURE.md` §11 (V2-D026). The operator has final authority over factual wording and final content.
